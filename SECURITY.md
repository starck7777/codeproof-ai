# Security and trust boundaries

Local-only prototype; do not expose it to a network. No user authentication or ownership model is implemented. Host/origin checks, loopback bindings, parameterized ORM queries, request limits and process-local rate limits reduce accidental exposure but do not substitute for authentication. A malicious local user/process can access the API. Rate limits are per API process, so use a shared limiter before scaling.

Execution containers are non-root, offline, read-only root, all capabilities dropped, no-new-privileges, constrained CPU/memory/PIDs/file descriptors/file size/tmpfs and wall time. Source and trusted test mounts are read-only. There is no home, credential, host-network or Docker socket mount. Only the trusted host worker holds Docker authority. Cleanup removes only the specific generated container name in finally. Hard worker termination needs stale recovery; the fixed inner runner also has its own short timeout. Docker alone is not a complete defense against hostile code or kernel escapes. Public multi-tenant use needs dedicated disposable VMs/microVMs, separate worker hosts, strong auth/authorization and stronger artifact/process isolation.

Tools do not accept shell commands; only fixed argument arrays execute. Source writes allow exactly `solution.py`, bound size, reject traversal/absolute paths/backslashes/symlinks. No archives or arbitrary URL fetch features exist. Gateway origins come only from operator environment, exact allowlist with no redirects/proxies or embedded credentials. A compromised operator configuration can permit a dangerous origin; do not allow arbitrary tenants to configure it. DNS-based origins should be pinned/restricted with egress policy; loopback gateway is the default.

Agent source/output is data, never privileged instructions. React renders text, preformatted output and diffs using escaped text children; no raw Markdown/HTML injection. Exported HTML is escaped with restrictive CSP, downloads use generated safe filenames, and CSV contains only constrained identifiers/enums/numbers. Reports exclude server credentials. Traces redact configured gateway secrets and common authorization fields and truncate output. Do not store credentials in task source; secret redaction is not a DLP guarantee.

The trusted evaluator parent owns expected results and grades candidate JSON, replacing the earlier candidate-writable pytest-report design. Hidden fixture directories never enter agent tool responses or workspace mounts. Only source is copied into a fresh evaluator. Candidate code can inspect evaluator fixtures while grading, but no subsequent repair call occurs. This is not protection against all adversarial attempts to introspect same-UID parent processes. A stronger cross-UID/VM evaluator is needed for adversarial public submissions.

## Verification and scanner review

`make verify` runs Ruff, Bandit (medium+ gate), detect-secrets on publishable files and all Git revisions, pip-audit, npm audit, security/API/persistence tests and Docker/browser checks. Scanner success does not prove absence of vulnerabilities. See FINAL_TEST_REPORT.md for actual results and blocked tests.

The fixed container-private tmpfs mount has one narrowly documented B108 annotation; it is not a shared host temporary file. The runner uses OS-generated temporary directory/file names. Bandit low findings are reviewed expected uses: subprocess in sandbox and container runner has fixed argument arrays, no shell and controlled executable paths; `/tmp` is a fresh container tmpfs, with no other tenant. Candidate stdout is file-size limited. Backend subprocess controls an operator-installed Docker CLI found through PATH; only run the trusted worker with a trusted PATH. These are not suppressed globally; medium/high findings fail verification. Docker/tempfile usage needs runtime integration tests in addition to source review.

Initial npm audit found vulnerable Vite/PostCSS and minimatch through typescript-eslint. Vite/PostCSS were upgraded; a targeted minimatch 11.0.1 override resolves the advisory while preserving working lint/build checks. Recheck compatibility on future upgrades. Public local-only PostgreSQL demo password and synthetic test credentials have narrow inline scanner annotations; no real credentials are intended. Never reuse this password in a remotely accessible database.

Dependency versions are locked; base image patch age and container image vulnerability scanning remain a limitation. Rebuild against patched digest-pinned base images before production. Git history is scanned without deleting or rewriting it. If a real secret is detected, stop publication and rotate it; removing a current file does not revoke a leaked key.
